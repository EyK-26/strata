Canonical artifacts and retained boundaries
- contracts/token: sole fresh-symbol opaque token construction/inspection implementation; same labels do not alias. container/core/bootstrap reexport the same factory.
- contracts/services: sole service descriptor brands/helpers; graph validation consumes these declarations, ServiceContainer alone owns values/initialization/cache.

- contracts/container: canonical engine plus deliberately quarantined legacy methods below; no dist/index shim.
- contracts/serviceTokens: canonical compatibility facade, retaining listed old string keys and old type-only coupling until their migrations.
- config/applicationConfig: explicit-input adapter; config/configSnapshot is private shared plain-data validation/copying. runtime/application imports the snapshot helper, never the adapter or envSchema. Legacy envSchema's ambient default remains outside the neutral owner graph; the target adapter always supplies input.
- runtime/serviceGraph is private validation/ordering/startup orchestration, not another value cache. No public helper subpath added.

Boundary enforcement scope and limits
The exact neutral DAG is encoded in scripts/check-application-boundary.ts, including private serviceGraph/configSnapshot and the explicitly bounded legacy serviceTokens facade. Dependency changes require changing that named graph plus positive/negative fixtures; there is no wildcard allowance for contracts/runtime modules. Bun validates executable syntax/import kinds; a TypeScript lexical scan retains erased type-import edges. Ambient checking is deliberately conservative and reserves banned identifiers even for local bindings/method names; it is not arbitrary-code sandboxing or general scope analysis. No Node service or added parser dependency is required.
The standalone bundle verifier rejects root shims/noncanonical runtime imports and verifies build externalization. Installed mixed-import runtime/type evidence is required independently; source aliases alone cannot establish package identity.
