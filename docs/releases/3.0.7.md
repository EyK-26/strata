# Strata 3.0.7

This release carries forward the application-authoring improvements and correctness
fixes prepared for 3.0.6 across all five Strata packages. The v3.0.6 release workflow
stopped at its quality gate before npm publication because an existing SAML
acceptance test still expected login without browser-bound state.

See the [3.0.6 change summary and upgrade notes](3.0.6.md) for the full framework
changes, including consumer API changes, generated application updates, database
and queue shutdown fixes, and authentication protections. Upgrade the selected
Strata packages together to **3.0.7**. Existing generated applications still need
the documented bootstrap and authentication-route updates.

## Release acceptance fix

- Require the transient SAML state cookie for successful login and MFA in the
  installed-app security test.
- Verify missing or mismatched browser state is rejected without creating a session.
- Supply matching state when testing unsigned assertions, incorrect audiences and
  incorrect issuers, so those tests exercise assertion validation itself.
- Check secure state-cookie attributes and clearing after successful login.

The correction changes acceptance tests, not the runtime authentication behavior
introduced in the preceding audit. Release quality gates remain enabled.

## Validation and publication

The affected installed-app security suite passed all 24 tests. A separate SAML-only
run passed with a fresh generated fixture. Type checking and formatting also passed.
These checks manually supply cookies over loopback HTTP; they do not qualify
browser HTTPS cookie delivery. Full CI and release validation remain required.

After merging PR #412, tag the intended merged commit as `v3.0.7` when ready to
release. The existing `v3.0.6` tag remains unchanged; rerunning it would execute the
old failing test. This preparation does not create a tag or publish packages.
