# Strata 3.0.6

This release brings the application-authoring improvements and correctness fixes
merged in PRs [#407](https://github.com/EyK-26/strata/pull/407),
[#408](https://github.com/EyK-26/strata/pull/408),
[#409](https://github.com/EyK-26/strata/pull/409) and
[#410](https://github.com/EyK-26/strata/pull/410) to all five packages:
`@getstrata/core`, `@getstrata/bootstrap`, `@getstrata/cli`,
`@getstrata/starter` and `create-strata`.

## Application development

- Compose applications with `defineApp` and `serveApplication`; shared bootstrap,
  account and database workflows replace copied infrastructure.
- Use concise model declarations, declarative providers with setup/boot phases,
  `defineMigration`, and model/event listener helpers. Persistence ownership,
  model/repository registration and account mapping remain explicit.
- Generate simpler modules and working factories in `src/db/factories`. Scaffold
  commands validate names and paths, honor configured module directories and keep
  help free of filesystem side effects.
- Use Bun-backed streaming storage, structural mail/storage interfaces and
  application-owned notification channels. MySQL keeps its qualified optional
  `mysql2` adapter and preserves exact oversized integers.
- Generated apps contain only the selected frontend assets/views. Test controls
  use dedicated testing entrypoints instead of production imports.

## Correctness and security

- Validate captured configuration before schema effects, preserve provider phase
  order, and anchor relative SQLite/storage paths to the application root.
- Preserve canonical application/listener token identity in installed packages.
- Seal MySQL/PostgreSQL shutdown admission, share native cleanup acknowledgements,
  drain admitted MySQL transactions, prevent retained connections from reopening,
  and drain synchronous queue jobs before close completes.
- Fix the immediate outbox worker start/stop race, eager CLI adapter loading,
  short JWT lifetime regression and misleading session TTL diagnostics.
- Require purpose-bound password-confirmation proofs and browser-bound GitHub/SAML
  sign-in state. Retain OIDC PKCE, SAML assertion validation and SQL replay protection.
- Share form-request validation, validate integer query parameters and notification
  IDs, preserve notification HTML, and require atomic tagged-cache loading.

## Upgrade notes

This release includes consumer API and generated-layout changes; review these
steps even though the packages advance together within the existing 3.0 series.

1. Upgrade the selected Strata packages together. Existing generated apps are not
   rewritten by a package installation: adopt the current bootstrap and auth-route
   changes explicitly.
2. Move removed test-control imports to `@getstrata/core/testing` or
   `@getstrata/bootstrap/testing`. Use the current scaffold model/factory/module
   layouts and keep explicit registration.
3. Implement `getOrSetTagged` in custom cache stores. Configure notification
   channels explicitly; the built-in database channel requires positive
   safe-integer user IDs.
4. Existing password-confirmation cookies need one fresh password confirmation.
   Ordinary login sessions remain valid.
5. Custom `verifyOAuthState` callers must issue the corresponding browser-state
   cookie. Apply the generated GitHub/SAML callback updates to existing apps.
   Browser SAML requires HTTPS because its separate short-lived state cookie uses
   `SameSite=None; Secure`.

[retrospective audit](../architecture/retrospective-correctness-audit.md) for detailed

## Validation and publication

The merged implementation passed 4,072 unit/integration tests with two existing
MySQL/RLS skips. The coverage gate passed with unchanged exemptions. Typecheck,
lint, builds, package-boundary checks, packed SAML acceptance and GitHub/OIDC
integration smoke checks also passed. These are local fixture results, not live
external-provider or production-capacity qualification.

This is release preparation. After merging the version PR, the maintainer can tag
the intended `main` commit as `v3.0.6` and run the existing release workflow when
ready. This PR does not create a tag or publish packages; the release workflow
retains its own quality gate.
